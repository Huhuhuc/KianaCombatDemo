# Crash Fix: Empty AnimInstance

## Symptom

Pressing the attack input caused `EXCEPTION_ACCESS_VIOLATION` in `AKianaCharacter::PlayAttackMontage()`.

## Cause

The old implementation called `GetMesh()->GetAnimInstance()->Montage_SetEndDelegate(...)` without checking whether the skeletal mesh had a live AnimInstance. A missing, not-yet-initialized, or temporarily swapped AnimClass made `GetAnimInstance()` return null.

## Fix

All montage end delegates now go through the local `BindMontageEnd` helper in `KianaCharacter.cpp`. It checks the mesh, montage, and AnimInstance before binding. The gameplay path can therefore fail to play a montage safely instead of dereferencing a null AnimInstance.

The enemy attack state flow was also corrected: entering `Attack` now starts the montage and timers in one function, then transitions to `Recover` only after the montage duration timer fires.

## Verification

- `KianaCombatDemoEditor` builds successfully with UE 5.8.1.
- The C++ classes load after restarting the editor.
- PIE starts in `L_CombatArena` and spawns `BP_KianaCharacter_Cpp` plus `BP_StrikeJaeger_Cpp`.
