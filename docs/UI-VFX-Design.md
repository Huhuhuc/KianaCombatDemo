# 战斗验收与 UI / 特效设计

更新：2026-10-04。当前验收以 [验收台账](Acceptance-2026-10-04.md) 为准。以下布局和高级反馈部分保留为设计方案，不表示逐项已实装。

## 当前状态

2026-10-03 保存的敌人回归为 12/12 通过。旧的背后轻/重受击失败结论已被新报告替代；新版敌人回归将急停出现检查改为动作后恢复移动，不能宣称原急停用例也通过。玩家急停由 MovementRecovery.json 单独覆盖。

快速五次点击仍有限制：0.12 秒和 0.35 秒间隔未到第五段，0.55 秒通过。AttackReleaseCheck 的通过只说明顺序有界和无新输入回到待机，不代表任意频率五连。实体手柄、正常速度四敌人及镜头体验仍待验。

HUD、首页、难度选择、生命/冷却、伤害数字、胜负重试已有实现。Niagara 最小命中、技能和闪避触发已接入源码，2026-10-04 编辑器目标编译成功，运行验证另记。复杂寻路、完整动画图及高级轨迹尚未实现。旧锁定风险应结合现有源码和实机复核，不能直接沿用为当前已复现缺陷。
## 三种范围选择

推荐：最小战斗 HUD + 真实命中反馈。优先显示生命、技能冷却、锁定及重试，随后添加少量攻击轨迹和命中特效。
更小范围：只做血条，成本低，但冷却、死亡重试仍不完整。
更大范围：完整角色面板、评分、连击评级和大招演出，会扩大状态和素材需求，不适合当前稳定阶段。

## 推荐布局

- 左下：角色名称、生命条、当前 / 最大生命。低血量只让血条变色，避免持续全屏闪烁。
- 右下：普攻、闪避、技能图标与当前设备按键；技能冷却遮罩及剩余秒数。无闪避资源机制时不虚构耐力或闪避次数。
- 敌人头顶：生命条，受击或锁定时显示；离屏隐藏，死亡时淡出。
- 锁定目标胸口附近：小型标记，遮挡时隐藏；解除锁定立即消失。
- 中央区域保持清晰，供敌人前摇和攻击动作展示。
- 玩家死亡：失败提示、重试、返回；敌人死亡：胜利提示、再次挑战。重试完整重载战斗场，清理旧计时器和状态。

生命条主条立即更新，后方损失条延迟约 0.15 秒后在约 0.3 秒内追上。UI 只显示真实战斗数据，不自行扣血。

## 攻击反馈

第一层：先做无粒子的血条变化、目标短暂受击高亮、可关闭的伤害数字。数字只由实际伤害事件产生；无敌闪避不出现扣血数字。

第二层：根据逐段动画实际接触部位放置短促轨迹。手、脚或武器插槽必须现场核对，不预设全部五段都是武器斩击。轨迹由动画通知窗口控制，中断、死亡和切换动作时必须关闭。

第三层：真实命中点的小型 Niagara 冲击，普通攻击短且小，末段和技能稍强。未命中只播放挥击轨迹，不能生成命中特效。现有范围判定需要补充可信接触点，不能把所有粒子固定在敌人中心。

闪避仅加短残影或地面滑动尘，不让视觉残影代表额外无敌时间。敌人攻击前摇先用清楚的动作及轻量提示，不能让玩家特效遮住敌人。

暂不增加全局慢动作、全屏闪白、强震屏或长时间顿帧。当前主要目标是消除停顿；后续命中停顿、相机震动、手柄震动必须分别可调且可关闭。

## 数据与实现边界

UMG Widget Blueprint 负责布局，C++ 提供生命变化、实际命中、技能冷却、锁定、设备切换和战斗结束事件。已有 GetHealthPercent 可复用；数值文本需提供当前和最大生命的只读接口。

命中反馈携带伤害、目标、攻击段、接触位置及普通/技能类型。表现层不得修改伤害、连招计时或无敌窗口。按键提示按最后实际输入设备更新，并做短暂切换延迟以免摇杆漂移造成提示闪烁。

HUD 使用屏幕锚点和 DPI 缩放，至少检查 1920×1080 与 1280×720。粒子采用固定生命周期、并发上限及池化；连续战斗不允许组件数量持续增长。

## 实施顺序与验收

1. 修正锁定朝向冲突，验证相机、五连击、闪避无敌与受击恢复；实体手柄长按、松开、中断、断连需测试。
2. 接入生命 / 冷却 / 锁定 HUD 与战斗结束重试；验证显示与实际伤害一致。
3. 在每段动画上标记挥击窗口，加入最小命中特效；空挥、无敌、死亡不产生错误反馈。
4. 同场景比较特效开启与关闭的帧时间，持续战斗检查粒子清理及视线遮挡，再调节视觉强度。

进入下一阶段的门槛：正常速度完成攻击、被攻击、闪避、技能、击杀与死亡；没有状态卡死、持续漂移、松手仍自动攻击或重试残留。主观手感由实际游玩确认，不以编译通过代替。
